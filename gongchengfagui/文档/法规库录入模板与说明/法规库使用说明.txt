============================================================
  工程建设法规 AI 知识库 · 第二版 · 法规源与更新说明
============================================================

本文件是整个知识库的【法规源说明】。所有法规以 Markdown(md) 文件存放，
脚本据此一键重建检索数据。日常你只需做三件事：

  ① 让 AI（豆包等）生成规范 md，放进「法规库/0新录入」
  ② 双击「法规库/rebuild.bat」
  ③ 本地浏览器刷新 index.html 查看结果


------------------------------------------------------------
一、日常三步工作流（最常用，照做即可）
------------------------------------------------------------
1) 生成规范 md
   - 打开「文档/法规库录入模板与说明/录入通用模板.md」（这就是你要的"模板"）。
   - 把该模板全文 + 法规链接/PDF/截图，一起发给任意 AI（豆包/通义/ChatGPT…）。
   - 让 AI 按模板生成一份带 Front Matter 的 .md 文档。
   - 把 md 存到「法规库/0新录入/」文件夹（已建好，空的）。

2) 一键更新（双击 法规库/rebuild.bat）
   脚本自动依次执行：
     [1/3] 自动归位 —— 把 0新录入 的文件按 level 搬进 01~12 层级文件夹
     [2/3] 校验     —— 检查 level 与文件夹是否匹配、是否有重复
     [3/3] 重建数据 —— 生成 data/manifest.json、data/search.json、laws/*.md
     [+1]  更新台账 —— 重新生成 法规清单.xlsx
   双击后稍等片刻，看到「完成」即可。

3) 查看结果
   - 本地浏览器打开 3第二版/index.html（检索/AI问答/阅读）。
   - Excel 打开 法规清单.xlsx（台账）。

备选：也可以手动把 md 直接放进 法规库/01-法律 … 12-政策解读 对应文件夹，
      再双击 rebuild.bat，效果完全相同（只是少了"自动归位"那一步动作）。

------------------------------------------------------------
三、脚本与批处理说明
------------------------------------------------------------
【rebuild.bat】— 一键总入口，双击运行
  用途：自动归位 → 校验 → 重建数据 → 更新台账。
  编码：UTF-8 with BOM（含中文，勿用记事本另存为 ANSI，否则乱码）。
  注意：只重建数据，不碰 app.js/app.css，不会破坏 AI 问答功能。
  需要本机装有指定的 Python（bat 内已写死路径）。

【check.py】— 法规库校验
  扫描 01~12 文件夹里的 md，报告：level 与文件夹不匹配 / 跨文件夹重复 /
  必填字段缺失（无 Front Matter / 无 level / 无 title）。
  单独运行：python check.py（退出码 0=无问题，1=有问题）。

【new_law.py】— 录入辅助（归位 / 扫描 / 向导）
  · python new_law.py scan         只读列出放错文件夹的 md（不改动）
  · python new_law.py place --all --go   把 0新录入 及放错的文件按 level 搬正
  · python new_law.py place 文件.md --go  归位单个文件
  · python new_law.py new          交互式录入向导（手填直接生成规范 md）
  原则：归类唯一依据是 Front Matter 的 level 字段；只移动、不改名、不建子目录。

【gen_xlsx.py】— 生成 法规清单.xlsx
  读取全部 md 的 Front Matter 重新生成台账（备注列会被保留，其它列由 md 覆盖）。
  单独运行：python gen_xlsx.py

【build_data.py】— 唯一安全的数据重建脚本
  读取 法规库/，输出 data/manifest.json + data/search.json + laws/*.md。
  被 rebuild.bat 调用；也可单独运行：python build_data.py


------------------------------------------------------------
四、关键约定与注意事项
------------------------------------------------------------
1. level 字段是"命根子"
   - 网页归类、文件归位、清单统计全靠 Front Matter 的 level 字段。
   - 合法值（与 01~12 文件夹对应）：
       法律 / 司法解释 / 中央行政法规 / 中央部门规章 / 中央规范性文件 /
       地方行政法规 / 地方规章 / 地方规范性文件 / 标准规范 /
       司法案例 / 行政案例 / 政策解读
   - level 写错 → 文件会留在 0新录入 并提示，改对重跑 rebuild 即可。

2. 地方类（06/07/08）平铺存放
   - 文件直接放 NN-层级 文件夹下，【不建省/市子目录】。
   - 地区由 Front Matter 的 region 字段（如「四川省」「四川省/成都市」）驱动网页地区树。

3. 文件名约定：日期-文号-标题.md
   - 日期 YYYYMMDD；文号里的 / 改为 -（如 GB/T50319-2013）。
   - new_law.py 只搬位置、不改名；文件名由生成 md 时（AI 或你）定好。

4. 已废止法规
   - status: 已废止，且必须加 superseded_by: 《替代它的法规名》。

5. verify_status
   - 初稿统一标 初稿待校核；正式对外引用前请逐条核对官方原文，核对后改 已校核 再 rebuild。

6. data/、laws/ 是派生文件
   - 由 法规库/ 的 md 生成，删掉双击 rebuild.bat 会自动再生，不影响功能。
   - 因此"精简数据"只需管 法规库/ 的 md，不用动 data/laws。


------------------------------------------------------------
五、★ 千万不要做的事（会破坏现有功能）
------------------------------------------------------------
✗ 不要运行 build_appjs.py / build_css.py（如果存在）—— 它们会从旧生成器
  重写 app.js / app.css，把你现在的 AI 问答功能整体覆盖掉。
✗ 不要用任何旧版 rebuild.bat（调用 ..\law-knowledge-base 生成器的版本）。
✗ 不要把 md 同名文件跨文件夹重复存放（check.py 会拦下）。

唯一安全的更新入口就是：法规库/rebuild.bat。


------------------------------------------------------------
六、同步到 GitHub 网页（你手动做，不自动化）
------------------------------------------------------------
本地 3第二版/ 改完、刷新 index.html 确认无误后：
  1. 把 3第二版/ 整个目录手动复制到部署目录
     （D:/github/homepage/Chears77.github.io/gongchengfagui/），覆盖同名文件。
  2. 在部署目录 git push 到 GitHub。
